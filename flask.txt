Como o Flask foi utilizado no projeto:

1. Criação da aplicação Flask:
- O arquivo principal é `app.py`.
- A aplicação é criada com `app = Flask(__name__)`.
- O Flask controla as páginas, rotas e regras principais do sistema.

2. Estrutura de rotas:
- `/` mostra o catálogo principal.
- `/produto/<int:id>` mostra uma peça individual e suas recomendações.
- `/login` realiza a autenticação administrativa.
- `/logout` encerra a sessão.
- `/admin` mostra o painel administrativo.
- `/cadastrar` adiciona uma nova peça.
- `/editar/<int:id>` edita uma peça.
- `/deletar/<int:id>` exclui uma peça.

3. Templates Jinja:
- Os arquivos HTML ficam na pasta `templates`.
- O Flask envia os dados do Python para o HTML utilizando `render_template()`.
- O Jinja exibe produtos, famílias e recomendações dinamicamente.

4. Banco de dados:
- O projeto utiliza PostgreSQL hospedado no Supabase.
- A conexão é feita através da biblioteca `psycopg2`.
- As informações de conexão ficam em variáveis de ambiente.
- A tabela principal é `produtos`.

5. CRUD:
- CREATE: cadastro de novas peças.
- READ: listagem e visualização das peças.
- UPDATE: edição das peças.
- DELETE: exclusão das peças.

6. Famílias e coleções:
- Os produtos são organizados em famílias através do campo `colecao`.
- `extrair_familia()` identifica a família principal.
- `organizar_familias()` agrupa e ordena as peças.
- `gerar_slug()` cria identificadores simplificados.

7. Machine Learning:
- O recomendador fica em `ml/recommender.py`.
- O sistema utiliza coleção, categoria e tags das peças.
- O TF-IDF transforma essas informações em valores numéricos.
- A similaridade de cosseno identifica as peças mais semelhantes.
- A página individual recebe até 3 produtos em `relacionados`.
- O resultado aparece em `RELATED ARCHIVE / MACHINE SELECTED`.

8. Área administrativa:
- O sistema possui login administrativo.
- A autenticação utiliza sessões do Flask.
- Cadastro, edição e exclusão são protegidos por `@admin_required`.

9. Variáveis de ambiente:
- Senha do Admin, SECRET_KEY e dados do banco ficam no `.env`.
- O `.env` não é enviado ao GitHub.
- No Render, essas informações ficam nas Environment Variables.

10. Execução:
- Localmente: `python app.py`.
- Em produção: `gunicorn app:app`.
- A aplicação fica hospedada no Render.
- O PostgreSQL fica hospedado no Supabase.

Resumo:
- O Flask é o núcleo da aplicação.
- Ele controla rotas, templates, autenticação, CRUD e integração com o recomendador.
- O projeto utiliza PostgreSQL, Supabase, Render e Machine Learning.
